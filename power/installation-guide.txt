It LOOKED like a failure, and the check written here originally was the reason.
A successful resume is visually identical to a cold boot: the machine really is
fully powered off, so it must come back through GRUB -> kernel -> initramfs
before the image is restored, and the password prompt you then get is
LockScreen.qml, which quickshell-greeter deliberately mirrors.

Corrected check, for next time:

    journalctl -b 0 -k | grep -iE 'hibernation entry|hibernation exit'
    python3 -c 'import time; print(time.clock_gettime(time.CLOCK_BOOTTIME)-time.clock_gettime(time.CLOCK_MONOTONIC))'

PASS = "hibernation exit" present, and the second number is the seconds spent
switched off. On a cold boot it is 0.0.

Four things that mislead, all of them normal:
  - Use -b 0, NOT -b -1. A successful hibernate restores the pre-hibernate boot
    id, so the resume continues the SAME journal boot. -b -1 is the session
    before it and shows nothing.
  - Do NOT grep "Image saved". The kernel snapshots memory first and writes the
    image to swap afterwards, so that line is printed after the snapshot and is
    not inside it. A restored log always ends at "Disabling non-boot CPUs".
  - Seeing GRUB is expected.
  - Being asked for a password is expected - it is the lock screen, not greetd.
    `loginctl list-sessions` shows whether a new session was really created.
  - Cheapest check: your terminals and windows are still open.

NOTE = "Unable to resume from device ... continuing boot process" on a COLD
       boot is normal. You have one at 17:42:15 - that was the boot after the
       battery ran flat, before the test. Unrelated.

--------------------------------------------------------------------------------
OPTIONAL — DISABLE USB WAKE FROM SLEEP
--------------------------------------------------------------------------------
Not installed, by your call. A jostled USB dongle in a bag can wake the
machine from S3. With the lid fix in place this self-corrects (resume ->
logind sees the closed lid -> re-suspends in seconds), and disabling it means
the external Galaxy80 keyboard can no longer wake the laptop.

If you ever want it:
    sudo install -m 644 ~/dotfiles/power/optional/99-no-usb-wake.rules /etc/udev/rules.d/
    sudo udevadm control --reload && sudo udevadm trigger -s pci
    grep XHC /proc/acpi/wakeup        # -> *disabled
