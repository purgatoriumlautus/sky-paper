PART A — RENAME admni -> segfault   (you do this ALONE, at a text console)
----------------------------------------------------------------

A0. PRE-FLIGHT (while still logged in normally as admni):

    # 1. Prove you can become root (if this fails, STOP — you'd need a live USB):
    su -            # type root password, then: exit

    # 2. Note anything that names admni explicitly (you'll fix these as root):
    sudo grep -rn 'admni' /etc/sudoers /etc/sudoers.d/ /etc/subuid /etc/subgid

    # 3. Make sure the repos are clean (nothing uncommitted you care about):
    for r in ~/celestia ~/dotfiles ~/laniakea; do echo "== $r =="; git -C "$r" status -s; done

A1. Go to a text console:  Ctrl+Alt+F3   ->  log in as  root

A2. End admni's graphical session:
    loginctl terminate-user admni
    pgrep -u admni        # should print nothing

A3. The rename (run as root, in this exact order):
    usermod -l segfault admni
    usermod -d /home/segfault -m segfault      # moves /home/admni -> /home/segfault (waits)
    groupmod -n segfault admni

A4. Verify:
    id segfault           # uid=1000(segfault) gid=1000(segfault) groups=...wheel...docker...
    ls -ld /home/segfault
    ls /home              # no 'admni' anymore

A5. Fix any stragglers from A0 step 2 (edit as root, change admni -> segfault):
    grep -rn 'admni' /etc        # e.g. /etc/subuid /etc/subgid /etc/sudoers.d/*

A6. reboot

A7. At the ly login screen, log in as  segfault . Then check:
    whoami                # segfault
    echo $HOME            # /home/segfault
    ls ~/celestia         # repo present at the new path

>>> If anything is wrong BEFORE A6, undo it as root:
    usermod -l admni segfault ; usermod -d /home/admni -m admni ; groupmod -n admni segfault
