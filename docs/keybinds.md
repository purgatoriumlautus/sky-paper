# Единая схема биндов: Linux-машины + рабочий Mac

Спецификация. Не конфиг — конфиги пишутся руками по этому документу.
Исходное ТЗ: `docs/keybinds-brief.md`.

Документ общий для обеих машин репозитория — `laniakea` (ThinkPad X280) и
`celestia` (ПК) — и для рабочего Mac. Всё, что ниже, обязано работать
одинаково везде; машинные отличия (мониторы, батарея, wifi) в схему биндов
не входят и живут в `CONTEXT.md` §5 каждой ветки.

---

## 0. Принцип

Пока ты **в режиме** (normal mode редактора) — буквы свободны, модификатор
не нужен. Как только ты **в терминале** — буквы это текст, и бинд без
модификатора просто напечатается.

Отсюда вся схема:

```
Пробел (leader)  →  действия ВНУТРИ редактора       (Пробел w = сохранить)
Alt              →  пересечение границ контейнеров  (Alt+t = тогл терминала)
Ctrl             →  правка строки в шелле           (Ctrl+U = стереть строку)
Super / Cmd      →  окна на десктопе                (Super+l = окно вправо)
```

Четыре яруса не могут столкнуться физически: `Super` не доходит до
терминального приложения, `Пробел` работает только в normal mode, `Ctrl`
живёт только в шелле, `Alt` перехватывается контейнером до шелла.

## 1. Модель vim: буфер / окно / вкладка

Без этого схема не читается, потому что в VSCode эти три вещи слиплись в
одну и называются «вкладка».

| Что | Определение | Сколько бывает |
|---|---|---|
| **буфер** | файл, загруженный в память | 50 штук, большинство не на экране |
| **окно** (split) | рамка на экране, показывающая буфер | сколько наделал |
| **вкладка** (tab) | **набор окон**, то есть раскладка целиком | обычно одна |

Главная ловушка: **вкладка в vim — это не файл.** В браузере и VSCode
20 файлов = 20 вкладок. В vim 20 файлов = 20 буферов и **одна** вкладка.

Классический vim этим и пользуется: работу «много открытых файлов»
делают буферы, вкладка нужна редко — когда нужны два разных **расклада
окон**.

**Здесь выбрано иначе: одна вкладка = один файл.** Файловый пикер и
дерево открывают каждый файл в собственной вкладке, `switchbuf` не даёт
прыжкам (`gd`, quickfix, диагностики) подменять файл в текущем окне.
Причина — буферы невидимы: полоска сверху может показать вкладки и не
может показать буферы, поэтому «что у меня открыто» без вкладок
неотвечаемо. Цена — вкладка перестаёт быть раскладкой окон; сплиты
внутри вкладки по-прежнему работают (`Alt+v` / `Alt+s`), но набора
раскладок больше нет.

Буферы никуда не делись и продолжают копиться под капотом (`:ls`) —
просто ими больше не навигируют.

Соответствие с VSCode:

| vim | VSCode |
|---|---|
| окно (split) | editor group |
| буфер | вкладка внутри группы |
| вкладка (tab) | — (аналога нет) |

## 2. Ярус 0 — физика. Два ремапа

| Что | Linux | Mac |
|---|---|---|
| `CapsLock` → `Ctrl` | keyd: `capslock = leftcontrol` | System Settings → Keyboard → Modifier Keys |
| порядок под большим пальцем | **стоковый, не трогаем** | Modifier Keys: `Command`→`Option`, `Option`→`Command` |
| leader | `Пробел` (было `F19`) | `Пробел` |

**Почему `Ctrl` на CapsLock.** `Ctrl+U/R/W/A/E` в fish жмутся постоянно, а
штатный `Ctrl` в нижнем углу заставляет мизинец уходить с домашнего ряда.
CapsLock лежит прямо у мизинца, это единственный модификатор на домашнем
ряду. Настоящий CapsLock оставить на `Shift+CapsLock`, как сейчас.

**Почему leader уезжает с `F19` на `Пробел`.** macOS умеет превратить
CapsLock только в Control, Option, Command, Escape или Globe. **В `F19` —
не умеет, такой настройки нет.** Текущий leader на маке невоспроизводим
никак. Побочный эффект: keyd перестаёт быть обязательным звеном, схема
едет на любую клавиатуру — включая встроенную в макбук.

**Почему подгоняем мак, а не Linux.** Стоковый PC — `Ctrl | Super | Alt |
SPACE`, стоковый мак — `fn | Control | Option | Command | SPACE`. Если
считать **от пробела наружу**, `Alt` на PC первый, а на маке второй.

Правится это **на маке**, по трём причинам:

1. `Alt` несёт ярус контейнеров (`Alt+t`, `Alt+hjkl`, `Alt+Space`) — самый
   горячий модификатор схемы, и он должен быть прямо под расслабленным
   большим пальцем. Стоковый PC его туда уже кладёт.
2. `Super+hjkl` и `Super+1..9` управляют niri весь день. Сдвинуть `Super` —
   самое дорогое изменение, какое можно сделать на этой машине.
3. macOS переназначает **все** модификаторы нативно (System Settings →
   Keyboard → Modifier Keys). Для позиций модификаторов мак как раз гибкий,
   так что принцип «сложность на машину с правами» здесь не работает.

На маке: `Caps Lock → Control`, `Command → Option`, `Option → Command`.
Получается `fn | Control | Command | Option | SPACE`, и обе машины
сходятся: первая от пробела — `Alt`, вторая — `Super`/`Command`.

Цена — `Cmd+C/V/S/Tab` переезжают на соседнюю клавишу, и настройка на маке
привязана к конкретному устройству ввода.

**Обязательно:** убрать `grp:alt_shift_toggle` из `niri/config.kdl` —
`Alt+Shift` теперь несёт ресайз, иначе каждый ресайз переключал бы раскладку.

Замена — **левый нижний `Ctrl`, одной клавишей**. После того как `Ctrl`
переехал на CapsLock, угловая клавиша ничего не делает, и она уходит под
переключение языка: одно нажатие, без аккорда.

Напрямую это не работает. keyd заставляет CapsLock слать тот же
`leftcontrol`, и xkb их не различает — любой одиночный тап по CapsLock
переключал бы язык. Поэтому keyd шлёт с угловой клавиши **Menu** (`compose`,
keycode 135), а xkb вешает на неё `ISO_Next_Group` через `grp:menu_toggle`.
Menu вообще не модификатор, так что удержание не может сработать как AltGr,
и `Shift+Menu` по-прежнему даёт настоящий Menu.

**Когда применится.** Выяснено эмпирически: niri применяет xkb-опции только
в момент **подключения** клавиатуры, а не при перечитывании конфига. Конфиг
он перечитывает исправно (видно в journal), но живая клавиатура остаётся на
keymap из начала сессии. `sudo keyd/install.sh` перезапускает keyd, что
пересоздаёт его виртуальную клавиатуру — то есть включает обе половины
разом.

На маке переключение остаётся системным (`Ctrl+Space` — дефолт macOS).
Это единственное место схемы, где машины расходятся: одиночная клавиша,
а не аккорд, поэтому мышечная память страдает минимально.

Проверено на конфликты: `Ctrl+Space` не занят ни в nvim, ни в tmux, ни в
fish, ни в kitty.

## 3. Ярус `Alt` — границы контейнеров

Главный слой: именно он даёт «мозг не переключается между машинами».

Колонка «кто ловит» существенна: на Linux нажатие идёт по цепочке
`kitty → tmux → (nvim | fish)`, и кто поймал первым, тот и съел.
В `tmux.conf:1` стоит `unbind-key -a -T root` — root-таблица пустая,
поэтому всё, что не забиндено в tmux явно, **проходит насквозь** в панель.

| Бинд | Кто ловит на Linux | Что делает | Mac (VSCode) | Команда VSCode |
|---|---|---|---|---|
| **`Alt+t`** | **nvim** (toggleterm) | тогл терминала внутри nvim | тогл панели терминала | `workbench.action.terminal.toggleTerminal` |
| `Alt+h` | tmux **+** nvim | фокус влево | группа редактора влево | `workbench.action.focusLeftGroup` |
| `Alt+j` | tmux **+** nvim | фокус вниз | вниз, в терминал | `workbench.action.terminal.focus` |
| `Alt+k` | tmux **+** nvim | фокус вверх | вверх, в редактор | `workbench.action.focusActiveEditorGroup` |
| `Alt+l` | tmux **+** nvim | фокус вправо | группа редактора вправо | `workbench.action.focusRightGroup` |
| `Alt+Shift+h/j/k/l` | tmux **+** nvim | ресайз | ресайз группы | `workbench.action.increase/decreaseViewSize` |
| `Alt+v` | tmux **+** nvim | вертикальный сплит | split editor right | `workbench.action.splitEditor` |
| `Alt+s` | tmux **+** nvim | горизонтальный сплит | split editor down | `workbench.action.splitEditorDown` |
| `Alt+q` | tmux **+** nvim | закрыть окно/панель | закрыть редактор/терминал | `workbench.action.closeActiveEditor` |
| `Alt+z` | tmux | zoom панели | maximize группы | `workbench.action.toggleMaximizeEditorGroup` |
| `Alt+1..9` | tmux | окно tmux N | вкладка редактора N | `workbench.action.openEditorAtIndex1..9` |
| `Alt+n` / `Alt+p` | tmux | следующее / предыдущее окно | следующая / предыдущая вкладка | `workbench.action.next/previousEditor` |
| `Alt+Space` | tmux | `sesh` popup — прыжок в проект | Open Recent | `workbench.action.openRecent` |
| `Alt+Enter` | tmux | новое окно tmux | новый терминал | `workbench.action.terminal.new` |
| `Alt+u` | tmux | copy-mode (скроллбэк) | поиск в терминале | `workbench.action.terminal.focusFind` |
| `Alt+r` | tmux | перечитать `tmux.conf` | Reload Window | `workbench.action.reloadWindow` |
| `Alt+d` | tmux | detach | — | — |

### 3.1 `Alt+t` живёт в nvim

Это центральный бинд: работает **с обеих сторон границы** — из редактора
открывает терминал, из терминала возвращает. Ровно то, что сейчас делает
`F19 t`/`F19 q` (`init.lua:709-714`), но воспроизводимо на маке.

Значит в nvim он должен быть забинден **в обоих режимах** — normal и
terminal. И tmux не должен биндить `Alt+t` вообще, иначе nvim его не
увидит.

### 3.2 Сплитит тот, у кого фокус

`Alt+h/j/k/l`, `Alt+v/s/q` и `Alt+Shift+h/j/k/l` — единственные бинды,
живущие в двух местах одновременно.

| Ты сейчас в | `Alt+v` делает |
|---|---|
| nvim | сплит nvim — второй файл рядом, **тот же процесс** |
| голом fish | `split-window` в tmux — вторая панель с шеллом |

Это принципиально: `split-window` в tmux даст два **отдельных процесса**.
Два файла в одном nvim так не откроешь — не будет ни общего буфер-листа,
ни общего yank-регистра, ни `:diff`.

Механизм — тот же, что у `vim-tmux-navigator`. В tmux бинд оборачивается
в `if-shell`, который проверяет, что запущено в панели (`ps` по
`#{pane_tty}` с грепом на `nvim`). Если nvim — `send-keys`, нажатие
проходит насквозь. Если нет — tmux выполняет своё действие сам.
Для `hjkl` этим занимается сам плагин; для `v/s/q` то же условие пишется
руками, три строки.

Одно правило в голове: **`Alt+v` = «дай ещё одну панель рядом»**, а кто её
даст — не твоя забота.

### 3.3 Почему `Alt`, а не `Ctrl`

`Ctrl+hjkl` отбирает у шелла `Ctrl+H` (= Backspace, байт `0x08`),
`Ctrl+J` (`0x0A`), `Ctrl+K` (твой `kill-line`, `config.fish:122`) и
`Ctrl+L` (очистка экрана). `Alt` с fish не конфликтует вообще, и это уже
твоя мышечная память из tmux.

### 3.4 Про цифры

`Alt+1..9` владеет **самый внешний контейнер** — tmux на Linux, VSCode на
маке. Вкладки nvim (которые layout, см. §1) остаются на `Пробел 1..9`.

### 3.5 На маке обязательно

`terminal.integrated.macOptionIsMeta: true`. Без неё macOS считает Option
клавишей композиции и `Option+h` даёт `˙`. Весь ярус `Alt` мёртв.

## 4. Ярус `Пробел` (leader) — редактор

Ноль модификаторов, последовательные нажатия. Работает в nvim и в
VSCode+Vim одинаково.

**Leader — это дерево, а не список.** `Пробел g` — вход в гитовую ветку,
дальше ещё буква. Каждая ветка держит ~10 биндов, веток 20+. Твои
нынешние 50 биндов влезают с запасом.

### 4.1 Верхний уровень

| Бинд | Действие |
|---|---|
| `Пробел Пробел` | **открыть файл** (fuzzy) |
| `Пробел ,` | список открытых вкладок, прыгнуть в любую |
| `Пробел Enter` | новая пустая вкладка |
| `Пробел /` | grep по проекту |
| `Пробел :` | история команд / command palette |
| `Пробел w` | сохранить |
| `Пробел q` | закрыть вкладку |
| `Пробел e` | дерево файлов |
| `Пробел h` | dashboard |
| `Пробел 1..9` | вкладка N (= файл N, см. §1) |

`Пробел Пробел` — самое частое действие, самый дешёвый бинд: двойное
нажатие большим пальцем.

`Пробел w` = **write**, не window. Оконный namespace целиком забрал ярус
`Alt`, поэтому `w` освободилась под очевидное значение.

### 4.2 Ветки

```
f  ФАЙЛЫ                    g  ГИТ                     c  КОД
 ff  файлы                   gg  lazygit                ca  code action
 fr  недавние                gs  status                 cr  переименовать
 fg  grep                    gd  diff                   cf  форматировать
 ft  вкладки                 gb  blame                  cd  диагностика строки
 fs  символы файла           gl  log                    cs  символы файла
 fh  help                    gp  preview hunk
 fk  список всех биндов      gr  reset hunk
                             gS  stage hunk

t  ВКЛАДКИ                  x  ОШИБКИ                  u  ИНТЕРФЕЙС
 tt  список                  xx  список диагностик      uw  перенос строк
 td  закрыть                 xq  quickfix               un  номера строк
 to  закрыть все кроме       xl  loclist                us  проверка орфографии
 tp  предыдущая                                         ut  тема
```

Ветка была `b` (БУФЕРЫ), пока файлы жили в буферах. С переходом на
вкладку-на-файл (§1) буферных действий не осталось, поэтому namespace
переехал в `t`, а не остался неверным ярлыком.

Свободны ещё `a b d i j k l m n o p r s v y z` — места больше, чем
понадобится.

### 4.3 Голые клавиши — без leader вообще

Половина работы в редакторе сюда и уходит. Это стандарт vim, **VSCodeVim
маппит их сам — на маке ноль конфига**:

| Бинд | Действие |
|---|---|
| `gd` | к определению |
| `gr` | найти использования |
| `K` | документация |
| `]d` / `[d` | следующая / предыдущая ошибка |
| `]c` / `[c` | следующий / предыдущий git-ханк |
| `gc` | закомментировать |
| `s` / `S` | flash-прыжок |
| `Ctrl+O` / `Ctrl+I` | назад / вперёд по местам, где ты был |
| `Shift+L` / `Shift+H` | следующая / предыдущая вкладка |

### 4.4 Много открытых файлов

Файлы не биндятся. Их открывают и по ним ходят — биндов всё равно пять,
сколько бы файлов ни было:

`Пробел Пробел` открыть → `Shift+L`/`Shift+H` листать →
`Пробел ,` прыгнуть в любой → `Ctrl+O`/`Ctrl+I` по истории переходов →
`Пробел q` закрыть.

Два файла рядом: `Alt+v` → `Пробел Пробел` → `Alt+h`/`Alt+l` между ними.

### 4.5 Запоминать не надо

`which-key`: нажал `Пробел`, подождал полсекунды — выехало меню веток.
Нажал `g` — показало гитовую ветку. Бинд не вспоминают, его **находят**.
На маке эквивалент — Command Palette.

### 4.6 Внутри дерева файлов

`h`/`l` закрыть/открыть узел, `H`/`L` root вверх/внутрь — как сейчас
(`init.lua`, nvim-tree). Открыть в сплите — привести к `Alt+v`/`Alt+s`
вместо нынешних `Ctrl+v`/`Ctrl+h`, чтобы словарь был один.

## 5. Ярус `Ctrl` — шелл. Vi-mode выключен

fish на обеих машинах один и тот же, поэтому поведение идентично по
построению.

**Vi-mode в шелле снимается** (`config.fish:72`:
`fish_vi_key_bindings` → `fish_default_key_bindings`).

Причина не в том, что он плохой, а в том, что дефолтные бинды fish — это
**ровно те бинды, которые macOS использует в любом текстовом поле
системы**: `Ctrl+A/E/K/Y`, `Option+Backspace`, `Option+←/→`. Одна мышечная
память на шелл, на поля ввода в маке и на VSCode. Vi-mode даёт третью
модальность там, где режимы не нужны — строка короткая, живёт секунду.

| Бинд | Действие |
|---|---|
| `Ctrl+A` / `Ctrl+E` | начало / конец строки |
| **`Ctrl+X`** | **скопировать всю строку в системный буфер** |
| `Ctrl+V` | вставить из буфера |
| `Ctrl+U` | стереть всю строку |
| `Ctrl+K` | стереть до конца |
| **`Alt+Backspace`** | **стереть слово назад** — как `Option+⌫` в macOS |
| `Ctrl+W` | стереть путь по компоненту |
| `Ctrl+Y` | вставить убитое |
| `Ctrl+P` / `Ctrl+N` | история назад / вперёд |
| `Alt+←` / `Alt+→` | по словам — **везде**, не только в шелле (§7.5) |
| `Ctrl+R` | fzf по истории |
| `Ctrl+T` | fzf по файлам |
| `Ctrl+G` | fzf cd |
| `Ctrl+L` | очистить экран |
| `Ctrl+D` | стереть символ вперёд — **не выход** (пресетный `exit` перебит: пустая строка + `Ctrl+D` убивала pane) |
| `→` / `Ctrl+F` | принять автоподсказку |

### 5.1 Что даёт дефолтный набор, а что надо дописать

`Ctrl+X` (`fish_clipboard_copy`), `Ctrl+V`, `Alt+Backspace`
(`backward-kill-word`), `Alt+←/→` — **встроены в пресет**, писать ничего
не надо.

Два расхождения с тем, что у тебя сейчас:

| Бинд | Дефолт fish | Что было у тебя |
|---|---|---|
| `Ctrl+U` | `backward-kill-line` — только до начала строки | `kill-whole-line` — вся строка |
| `Ctrl+W` | `backward-kill-path-component` — по сегменту пути | `backward-kill-word` — по слову |

`Ctrl+U` надо переопределить (`kill-whole-line` — тебе нужна вся строка).
`Ctrl+W` по сегменту пути для шелла удобнее дефолта — стоит попробовать
как есть.

Все `bind` теряют флаг `-M insert` (режимов больше нет), а `-M visual`
блок (`config.fish:113-116`) удаляется целиком.
Современный синтаксис fish принимает имена клавиш (`ctrl-u`, `alt-backspace`)
вместо escape-нотации (`\cU`).

### 5.2 Единственный неудобный аккорд

`Ctrl+A`: мизинец на CapsLock, `A` прямо под ним. Жать `A` **безымянным**,
это стандартный роллинг, привыкается за день. Все остальные — разные
пальцы или разные руки.

### 5.1 Списки с полем ввода — везде `Ctrl+j` / `Ctrl+k`

Голые `j`/`k` там невозможны, есть текстовое поле. Одно правило на три
места:

| Где | Статус |
|---|---|
| fzf | дефолт, уже работает |
| Telescope (insert mode) | дефолт, уже работает |
| VSCode Quick Open | настроить: `when: inQuickOpen` → `workbench.action.quickOpenSelectNext/Previous` |

С fish не конфликтует: пока открыт fzf, он владеет терминалом целиком.

### 5.2 Что должен отдать VSCode

| Настройка | Значение и зачем |
|---|---|
| `terminal.integrated.macOptionIsMeta` | `true`. Без неё ярус `Alt` мёртв. |
| `terminal.integrated.allowChords` | `false`. Иначе VSCode ловит `Ctrl+K` как начало своего аккорда и до fish он не доходит. |
| `terminal.integrated.commandsToSkipShell` | Массив id команд, которые VSCode обрабатывает **сам**, даже когда фокус в терминале. Элемент с префиксом `-` **удаляет** команду из дефолтного списка, то есть отдаёт нажатие шеллу. |
| `terminal.integrated.enablePersistentSessions` | `true`. Терминалы переживают обрыв SSH — закрывает единственное, ради чего там был бы нужен tmux. |

Порядок разбора конфликта: нажать в терминале, посмотреть, дошло ли до
fish. Если нет — найти команду в `Preferences: Open Keyboard Shortcuts` по
этому аккорду и либо снять бинд, либо добавить её с `-` в
`commandsToSkipShell`.

## 6. Ярус `Super` / `Cmd` — окна. Только Linux

На маке окнами ты не управляешь; `Cmd` там остаётся родным macOS/VSCode
модификатором. `Super` физически не доходит до терминального приложения,
значит этот ярус не может конфликтовать ни с чем ниже.

`niri` уже правильный («модификатор = глагол, `hjkl` = направление»).
**Меняется только строка 17.** Бинды не трогаем:

| Бинд | Действие |
|---|---|
| `Super+h/j/k/l` | фокус колонки/окна |
| `Super+Shift+h/j/k/l` | перенести окно |
| `Super+1..9` | воркспейс |
| `Super+Shift+1..9` | окно на воркспейс |
| `Super+Enter` | kitty |
| `Super+e` | yazi |
| `Super+d` | лаунчер |
| `Super+q` | закрыть окно |
| `Super+f` / `Super+Shift+f` | maximize / fullscreen |
| `Super+Space` | control center |
| `Super+o` | overview |

Остальные ~40 биндов niri (ресайз колонок, consume/expel, floating,
tabbed, мониторы) — редкие, оставить как есть.

## 7. Копирование

### 7.1 `Super+C` / `Super+V` — один жест на обеих машинах

На маке копирование идёт через `Cmd` во **всех** приложениях. На линуксе —
через `Ctrl`, а `Ctrl` здесь занят: это редакторский модификатор шелла
(`Ctrl+A/E/U/K/W/Y`, fzf на `Ctrl+T/R`). Разъезд между машинами
устраняется на стороне PC.

Наивный ход — `Super+C → Ctrl+C` в keyd — мёртв: переписанный на уровне
evdev, он неотличим от настоящего `Ctrl+C`, то есть каждое копирование
в терминале слало бы SIGINT. Симметрично на вставке: `Ctrl+V` — это
visual-block в vim.

Выход — вторая, более старая конвенция буфера обмена, которую до сих пор
держат GTK, Qt, Chromium и Firefox: **`Ctrl+Insert` копировать,
`Shift+Insert` вставить**. Она не конфликтует ни с чем: `Insert` не несёт
смысла ни в fish, ни в tmux, ни в nvim.

```
палец жмёт      keyd отдаёт        приложение понимает
Super+C    →    Ctrl+Insert   →    copy      (браузер, GTK/Qt, kitty, VSCode)
Super+V    →    Shift+Insert  →    paste
```

`keyd/etc/keyd/default.conf`, секция `[meta]`. Работает потому, что keyd
предопределяет `meta` как `layer(meta)` = `meta:M`, и биндинги внутри слоя
не наследуют его модификаторы — Super с результата снимается. Остальные
Super-бинды (`Super+hjkl`, `Super+1..9` в niri) не затронуты.

Побочный плюс: `Insert` — не буква, поэтому кириллические дубликаты,
которые нужны почти всем остальным биндам в репозитории, здесь не нужны.
keyd матчит физические keycode'ы.

Цена, чтобы не переоткрывать: kitty и VSCode больше **никогда не увидят**
`Super+C` — keyd забирает нажатие ниже композитора. Поэтому они биндят
Insert-пару (`kitty.conf`, `docs/vscode/keybindings.json` через поля
`key`/`mac`). Из-за того, что `Shift+Insert` уехал на буфер обмена,
primary selection в kitty остался только на `kitty_mod+s`.

**Внутри терминала цепочка идёт дальше.** kitty вешает `Ctrl+Insert` не на
`copy_to_clipboard`, а на **`copy_or_noop`**: скопировать своё выделение, а
если его нет — **пропустить клавишу в программу**. Собственное выделение у
kitty бывает только мышью, а под tmux мышь принадлежит tmux, то есть в
реальной работе выделения нет никогда и клавиша идёт дальше:

```
Super+C → Ctrl+Insert → kitty (нет выделения) → tmux copy-mode: C-IC → wl-copy
                                              → nvim visual:    <C-Insert> → "+y
```

Один жест, три слоя. `y` в обоих остаётся основной клавишей.

Обратной пары `Shift+Insert` в nvim нет намеренно — kitty её съедает на
`paste_from_clipboard`, текст приходит bracketed paste'ом, и nvim с ним и
так справляется.

### 7.2 Super-дыры: почему tmux расщеплялся на `Super+S`

У tmux **нет Super в грамматике** — только `C-`, `M-`, `S-`. Приходящий бит
Super он сворачивает в Meta. Проверено: скормили tmux-серверу сырой
`\x1b[115;9u` (`Super+s`) — выполнился `split-window`, потому что `M-s` это
вертикальный сплит. `extended-keys on`/`always` ничего не меняют.

Всё, что niri забирает себе, до терминала не доходит. Утекают только дыры —
клавиши, где у niri нет `Mod+<key>`, а у tmux есть root-бинд `M-<key>`:
`s`, `n`, `p`, `u`, `z`, `/`, `` ` ``, `Shift+Q`. Их глотает kitty через
`discard_event`.

Именно `discard_event`, а не `no_op`: `no_op` в kitty означает «отвязать и
**отдать программе**» — ровно тот баг, который чиним.

`--allow-fallback=shifted,ascii` в этих строках даёт фоллбэк по физической
позиции клавиши, поэтому одна строка накрывает и `s`, и `ы`. Это то, что
kitty использует для собственных дефолтных шорткатов.

### 7.3 Весь ярус Super — таблица переводов

Один принцип: **палец жмёт то же, что на маке, keyd отдаёт приложению то,
что оно понимает.** Секция `[meta]` в `keyd/etc/keyd/default.conf`.

| Палец жмёт | keyd отдаёт | Почему именно это |
|---|---|---|
| `Super+C` | `Ctrl+Insert` | CUA-конвенция; `Ctrl+C` занят под SIGINT |
| `Super+V` | `Shift+Insert` | то же; `Ctrl+V` — visual-block в vim |
| `Super+X` | `Shift+Delete` | CUA-вырезание; в терминале не значит ничего |
| `Super+A` | `Ctrl+A` | альтернативы нет; безопасно (см. ниже) |
| `Super+Z` | `Ctrl+Z` | альтернативы нет; **есть цена** (см. ниже) |
| `Super+←` / `→` | `Home` / `End` | на маке `Cmd+←/→` — концы строки |
| `Super+↑` / `↓` | `Ctrl+Home` / `Ctrl+End` | на маке `Cmd+↑/↓` — концы документа |
| `Super+S` | **не переводится** | `Ctrl+S` = XOFF, заморозил бы терминал |

Redo приходит бесплатно: модификаторы слоя на результат не переносятся,
поэтому `Super+Shift+Z` даёт `Shift+Ctrl+Z`.

Стрелки заодно чинят утечку. niri не биндит `Mod+стрелки`, поэтому раньше
нажатие проваливалось в kitty, а tmux сворачивал Super в Meta и отдавал fish
`Alt+Left` — движение по словам от чужого модификатора. Тот же дефект, что
расщеплял панель на `Super+S` (§7.2).

**`Super+A` дёшево.** `Ctrl+A` по всей цепочке свободен или уже означает то
же самое: в браузере и GTK/Qt это выделить всё, в VSCode `selectAll`, в nvim
`<C-a>` и так перебит на `ggVG`, tmux сидит на дефолтном префиксе `C-b`. В
fish попадёт на beginning-of-line — у командной строки нет select all, так
что терять нечего.

**`Super+Z` дорого, и это осознанно.** В терминале `Ctrl+Z` — это SIGTSTP,
то есть `Super+Z` там подвесит текущий процесс вместо отмены. Лечится `fg`.
Обхода нет: keyd работает ниже композитора и терминал от браузера не
отличает, а второй конвенции для undo, в отличие от буфера обмена, не
существует. Принято потому, что undo в шелле не бывает, а в браузере — всё
время.

**`Super+S` не переведён намеренно.** Save тоже не имеет альтернативного
аккорда, но `Ctrl+S` в терминале — это XOFF: поток вывода замирает до
`Ctrl+Q`. В отличие от подвешивания, это выглядит как зависание, а не как
действие. Поэтому `Super+S` остаётся сырым Super (VSCode ловит его сам), а
kitty его глотает, чтобы он не утёк в tmux сплитом.

### 7.4 `Alt+←` / `Alt+→` — по словам везде

Расхождение было внутри одной машины: fish держит `alt-left`, а браузер и
GTK/Qt — `ctrl-left`. Палец каждый раз выбирал модификатор по приложению.

keyd переписывает `Alt+стрелка → Ctrl+стрелка`, и физически везде жмётся
Alt, как `Option+←/→` на маке. Ничего не теряется:

| слой | `Ctrl+←` |
|---|---|
| fish | `backward-token` — тоже по словам |
| nvim | `b` (дефолт vim) |
| VSCode Linux | `cursorWordLeft` |
| браузер, GTK/Qt | по словам ✓ |
| tmux, niri | стрелочных аккордов не биндят |

Выделение приходит бесплатно: модификаторы слоя на результат не переносятся,
поэтому `Alt+Shift+←` даёт `Shift+Ctrl+←` — выделить слово, как
`Option+Shift+←` на маке.

Только Left/Right. `Alt+↑/↓` не тронуты: в VSCode это «переместить строку»
на обеих машинах. `Alt+Backspace` не тронут по более жёсткой причине — в
пресете fish на нём `backward-kill-word`, а `ctrl-backspace` не забинден
вообще, так что перевод не перенёс бы функцию, а стёр.

Цена: `Alt+←` как «Go Back» в VSCode под Linux больше не нажимается. На маке
это `Ctrl+-`, то есть машины на этом бинде и так не совпадали.

Та же цена в браузере, и там она дороже: `Alt+←` в Firefox — это нативное
«Назад», а не второстепенный бинд. Поэтому история переезжает на
`Ctrl+O`/`Ctrl+I` (§9.3) — иначе браузер остался бы без «назад» с
клавиатуры вообще.

### 7.5 Строка команды — `Ctrl+X`

Исходная проблема (`λ` и `19:59` в копии) — симптом того, что копировались
**экранные ячейки** через `V` (`select-line`) в tmux copy-mode. Ячейки не
знают, где кончился промпт и началась команда.

`Ctrl+X` копирует **буфер командной строки**, а не экран. Ни промпта, ни
паддинга, ни правого промпта — по построению. Одно нажатие, и работает
одинаково на обеих машинах, потому что fish там один и тот же.

Это встроенный бинд дефолтного пресета (`fish_clipboard_copy`) — то есть
снятие vi-mode не только не сломало копирование, а сделало его дешевле,
чем было (`Esc v` + motion + `y`).

tmux copy-mode (`Alt+u`) остаётся только для скроллбэка вывода.

### 7.6 Через SSH — OSC 52

На безголовом корпоративном сервере `wl-copy` и `xclip` мертвы. Механизм
один: escape-последовательность с base64 в теле, которую перехватывает
терминал на дальнем конце.

**Настраивать ничего не надо.** `fish_clipboard_copy` из коробки перебирает
`pbcopy` → `wl-copy` → `xsel` → `xclip`, не находит ничего, и дальше сам
шлёт OSC 52 — нужен только `base64` и `TERM != dumb`. Переопределение в
`~/.config/fish/functions/`, которое тут раньше значилось необходимым, не
нужно. Конфиг сервера: `docs/remote/config.fish`.

**Требует проверки** — открытые issue microsoft/vscode #104138, #122083:
поддержка OSC 52 под Remote-SSH неполная. Проба:

```
printf '\033]52;c;%s\a' (printf hello | base64)
```

— и `Cmd+V` в любом поле.

## 8. VSCode: сделать keyboard-driven

### 8.1 VSCodeVim

**Единственная позиция во всей схеме, требующая установки софта.** Без неё
яруса `Пробел` на маке нет. Проверить в первую очередь.

Настройки: `vim.leader` (в `<space>`), `vim.useSystemClipboard`,
`vim.handleKeys` (какие аккорды отдавать самому VSCode, а не перехватывать
плагином), `vim.normalModeKeyBindingsNonRecursive` — массив объектов с
полями `before` (массив клавиш) и `commands` (массив id команд VSCode).
Через него вешаются leader-последовательности.

### 8.2 Vim-навигация по спискам

Вот что реально делает VSCode управляемым с клавиатуры. Дерево файлов,
результаты поиска, список расширений — это списочные виджеты, по умолчанию
ходят только стрелками.

Условие `when`: `listFocus && !inputFocus` — «фокус в списке, но не в
текстовом поле». Под ним голые буквы свободны:

| Клавиша | Команда | Паритет |
|---|---|---|
| `j` / `k` | `list.focusDown` / `list.focusUp` | vim |
| `h` / `l` | `list.collapse` / `list.expand` | nvim-tree |
| `Enter` | `list.select` | — |

### 8.3 tmux на маке — не ставить

Внутри терминала VSCode он подерётся сам с собой: VSCode перехватит
`Alt+hjkl` раньше tmux. Панели VSCode делают ту же работу, а
`enablePersistentSessions` закрывает переживание обрыва SSH.

Ярус `Alt` спроектирован так, что **набор биндов одинаков независимо от
того, кто их исполняет** — tmux+nvim дома, VSCode на работе.

## 9. Браузер — Vimium

Браузер — четвёртое место, где ты живёшь в normal mode: буквы свободны,
модификатор не нужен. По §0 он ложится ровно как редактор, значит и словарь
обязан быть тот же.

Всю секцию держит одно соответствие: **вкладка браузера = буфер**. Она же
и самый внешний контейнер — других в браузере нет. Поэтому у вкладок два
входа: `Alt` как у контейнера (§3.4) и `Shift+H`/`Shift+L` как у буфера
(§4.3). Это не дублирование, а две роли одного объекта.

### 9.1 Почему Vimium, хотя Tridactyl лучше по механике

У Tridactyl конфиг — файл на диске (`~/.config/tridactyl/tridactylrc`), то
есть обычный stow-пакет с `git diff`. И он умеет `set keyboardlayoutforce
true` — перехват по физическим keycode'ам с трансляцией в US QWERTY, кроме
текстовых полей. Это буквально `langmap` из §10, только на уровне физики, и
чинит в том числе хинты.

Обе вещи мертвы на маке. Автозагрузка `tridactylrc` работает только через
native messenger — бинарь **вне песочницы браузера**, ставится в систему
(`firefox-tridactyl-native`). На managed-маке его не будет, а без него
конфиг всё равно вставляется руками, то есть единственное преимущество
исчезает.

Схема обязана быть воспроизводима на обеих машинах, поэтому берётся
расширение, которое ставится в один клик везде. Цена — кириллица
закрывается дублями (§10), а не одной строкой.

### 9.2 Ярус `Alt` — вкладки

Контейнер в браузере один, поэтому из §3 выживают четыре бинда. У
остальных (`Alt+t/v/s/z/u/Space/r`) нет объекта, которым они бы управляли —
как `Alt+d` не имеет аналога на маке.

| Бинд | Действие | Кто исполняет |
|---|---|---|
| `Alt+1..9` | вкладка N | **Firefox нативно** — §3.4 выполняется бесплатно |
| `Alt+n` / `Alt+p` | следующая / предыдущая вкладка | Vimium |
| `Alt+q` | закрыть вкладку | Vimium |
| `Alt+Enter` | новая вкладка | Vimium |

`Alt+1..9` — единственное место схемы, где чужой дефолт совпал с ярусом
сам. Под Linux Firefox это штатный шорткат вкладок, конфигурировать нечего.

### 9.3 Голые клавиши — паритет с §4.3

Здесь основная работа: **дефолты Vimium инвертированы относительно схемы.**

| Клавиша | В схеме | Дефолт Vimium | Что делаем |
|---|---|---|---|
| `Shift+H` / `Shift+L` | предыдущий / следующий **буфер** | назад / вперёд по истории | перебить на вкладки |
| `Ctrl+O` / `Ctrl+I` | назад / вперёд по **истории** | не занято | добавить |
| `Shift+J` / `Shift+K` | — | вкладки | **снять** — словарь один |
| `s` / `S` | flash-прыжок | не занято | алиас на `f` / `F` |
| `j`/`k`, `gg`/`G`, `/`,`n`,`N`, `y`, `x`/`X`, `i` | — | совпадает | не трогаем |
| `Ctrl+D` / `Ctrl+U` | полстраницы | забиндено по умолчанию | не трогаем |

`s`/`S` на хинты — не натяжка: `f` в браузере делает ровно то же, что flash
в редакторе, — прыжок глазами в произвольную точку экрана. Обе клавиши
остаются рабочими, дефолт не снимается.

`d`/`u` (полстраницы у Vimium) остаются как есть: в браузере они ничего не
значат в vim-словаре, конфликта нет, отнимать нечего.

### 9.4 Ярус `Пробел` — только верхний уровень

Веток `f/g/c/b/x/u` из §4.2 нет: в браузере нет пятидесяти действий, дерево
вышло бы пустым. Берётся верхний уровень §4.1, и то не весь.

| Бинд | §4.1 | Браузер | Команда Vimium |
|---|---|---|---|
| `Пробел Пробел` | открыть файл (fuzzy) | открыть URL — история + закладки + вкладки | `Vomnibar.activate` |
| `Пробел ,` | список вкладок | список вкладок, прыгнуть в любую | `Vomnibar.activateTabSelection` |
| `Пробел e` | дерево файлов | закладки | `Vomnibar.activateBookmarks` |
| `Пробел q` | закрыть вкладку | закрыть вкладку | `removeTab` |

Пустыми осознанно:

- `Пробел /` — grep по проекту. Поиск по странице уже на голом `/`, это
  стандарт vim (§4.3-класс), дублировать нечего.
- `Пробел :` — command palette. `?` (`showHelp`) делает то же одной
  клавишей и работает по умолчанию.
- `Пробел w` — save. В браузере не бывает.
- `Пробел h` — dashboard. У Vimium нет команды «домой», только нативный
  `Alt+Home`.
- `Пробел 1..9` — цифры забрал `Alt` (§9.2).

**Цена, которую надо принять явно.** Как только `Пробел` становится
префиксом, Vimium перестаёт отдавать его странице, и скролл пробелом
умирает. Он уезжает на `j`/`k` + `Ctrl+D`/`Ctrl+U` — то есть туда, где он в
vim и находится.

### 9.5 Хинты — filtered mode, а не буквенный

Метки хинтов Vimium рисует из настройки `linkHintCharacters` (дефолт
`sadfjklewcmpgh`) и, пока хинты на экране, сравнивает нажатия с этими
строками. В RU-раскладке физическая `s` даёт `ы`, совпадения нет.

**Дубли `map` тут не работают** — ты не вызываешь команду, ты набираешь
метку. Переписать `linkHintCharacters` на кириллицу можно, но это одна
глобальная настройка: почини RU — сломаешь EN.

Выход — **filtered hints** (Options → «Use link text for filtering»):
метки становятся **цифрами**. Цифровой ряд на ЙЦУКЕН — те же цифры, что на
QWERTY, поэтому `f` начинает работать в обеих раскладках. Это галочка в
Options, а не строка конфига, и её надо ставить руками при установке.

Цена: цифровые метки на плотных страницах длиннее буквенных (три знака
против двух) и теряется хват по домашнему ряду `sadfjkl`. Взамен хинты
можно фильтровать, набирая текст самой ссылки.

### 9.6 Что в браузере уже работает от keyd

Ярус `Super` (§7.3) доходит до Firefox без единой строки конфига — он
переписывается в CUA-конвенцию ниже композитора:

| Палец жмёт | Firefox получает | Работает |
|---|---|---|
| `Super+C` / `Super+V` / `Super+X` | `Ctrl+Insert` / `Shift+Insert` / `Shift+Delete` | да, Firefox держит эту конвенцию |
| `Super+A` | `Ctrl+A` | выделить всё |
| `Super+Z` / `Super+Shift+Z` | `Ctrl+Z` / `Ctrl+Shift+Z` | undo / redo — §7.3 ради этого случая и написан |
| `Super+←` / `→` / `↑` / `↓` | `Home` / `End` / `Ctrl+Home` / `Ctrl+End` | по строке и документу |
| `Alt+←` / `Alt+→` | `Ctrl+←` / `Ctrl+→` | по словам в полях ввода |

Последняя строка — **не бесплатная**. `Alt+←` в Firefox это нативное
«Назад», и после §7.4 оно больше не нажимается. Именно поэтому история
уезжает на `Ctrl+O`/`Ctrl+I` (§9.3): без этого браузер остался бы без
кнопки «назад» с клавиатуры вообще.

### 9.7 Где живёт конфиг

Бинды Vimium лежат в storage расширения, а не в файле, поэтому
`install.sh` для них невозможен. В репозитории — `firefox/vimium-keymap.txt`
рядом с `user.js`; ставится один раз вручную через Options → Custom key
mappings. Файл авторитетен, живой браузер — нет.

Не работает нигде на `about:*`, `view-source:*`, `addons.mozilla.org` и
странице новой вкладки: WebExtensions туда не инжектятся. Ограничение
общее для всех подобных расширений, обхода нет.

## 13. Проверить эмпирически

1. **Ставится ли VSCodeVim на managed-маке.** Блокирующий вопрос — без него
   яруса `Пробел` на маке нет, отваливается половина схемы.
2. Проходит ли `Alt+h` в терминал VSCode после `macOptionIsMeta`
   (`read` в fish — приходит ли `\eh`).
3. `echo $TERM` в терминале VSCode под Remote-SSH.
4. Проба OSC 52 из §7.2.
5. Ставятся ли расширения в браузер на маке.
6. **Принимает ли Vimium `<space>` как префикс последовательности.**
   Блокирующий для §9.4 — если нет, весь leader в браузере отваливается и
   остаются только §9.2 и §9.3.
7. Доходит ли `Ctrl+O` до контент-скрипта или его съедает нативный
   «Открыть файл» в Firefox. То же для `Alt+n`/`Alt+p` — под Linux
   `Alt`+буква может дёргать акселераторы скрытого меню.
8. Что Vimium видит в RU-раскладке при **модифицированном** нажатии:
   `Alt+n` приходит как `<a-n>` или как `<a-т>`. От ответа зависит, нужны
   ли кириллические дубли на аккорды или только на голые буквы.
